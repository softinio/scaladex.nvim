1. INTRODUCTION                                        *scaladex-introduction*

scaladex.nvim searches Scala Packages (https://pkg.scalanews.net), an index
of every Scala library on Maven Central, and adds the one you pick to your
build. Search finds libraries by what they do as well as by name, so a query
like `parse markdown` works.

Requests run in the background and never block the editor.

==============================================================================
2. REQUIREMENTS                                        *scaladex-requirements*

- Neovim 0.10 or later
- `curl` on your `PATH`
- Optional: telescope.nvim, for |scaladex-telescope|

==============================================================================
3. USAGE                                                      *scaladex-usage*

                                                                   *:Scaladex*
:Scaladex [platform={platform}] [scala={version}] [query]
    Search for [query], or ask for it when left out, with the given filters
    (see |scaladex-filters|). Pick a project, then
    one of its modules (skipped when it has only one), and the configured
    action is applied to it: the dependency line is copied, inserted below
    the cursor, or the package page is opened. See |scaladex-configuration|.

    The pickers use |vim.ui.select()|, so they appear in whichever picker
    you have set up (Telescope, fzf-lua, snacks.nvim, …).

:Scaladex! [platform={platform}] [scala={version}] [query]
    Like |:Scaladex|, but opens the module's page on pkg.scalanews.net.

Example mapping: >lua
    vim.keymap.set("n", "<leader>si", "<cmd>Scaladex<cr>", { desc = "Search Scala packages" })
<

==============================================================================
4. CONFIGURATION                                      *scaladex-configuration*

Calling `setup()` is optional; it only changes the defaults: >lua
    require("scaladex").setup({
      -- pkg.scalanews.net, or another instance of it
      base_url = "https://pkg.scalanews.net",
      -- default filters; nil does not filter
      platform = nil,      -- "jvm", "js", "native", "sbt" or "mill"
      scala_version = nil, -- e.g. "3" or "2.13"
      -- seconds before a request is abandoned
      timeout = 10,
      -- what choosing a module does: "copy", "insert" or "open"
      action = "copy",
    })
<
"copy" puts the dependency line in the unnamed register and, when Neovim has
a clipboard, the system clipboard. "insert" puts it below the cursor line,
indented like that line. "open" opens the module's page in the browser with
|vim.ui.open()|.

5. BUILD TOOLS                                          *scaladex-build-tools*

The dependency line matches the build of the buffer the search started in:

- a buffer with `//> using` directives: scala-cli
- otherwise the nearest build definition above the file:
  `build.sbt`                       sbt     `"org" %% "name" % "1.0"`
  `build.mill`                      Mill    `mvn"org::name:1.0"`
  `build.mill` pinned to Mill 0.x,
  or `build.sc`                     Mill    `ivy"org::name:1.0"`
  `project.scala`, `.scala-build`   scala-cli `//> using dep org::name:1.0`
- no build found: scala-cli

The Mill version is read from `.mill-version`, `.config/mill-version` or the
`//| mill-version:` header of `build.mill`; without one Mill 1 is assumed.

A library published only for Scala.js or Scala Native gets the cross-platform
form: `%%%` for sbt and `::` before the version for Mill and scala-cli. sbt
plugins always get `addSbtPlugin(...)`, and Mill plugins a `//| mvnDeps:`
header entry (`import $ivy` for Mill 0.x).

==============================================================================
6. FILTERS                                                  *scaladex-filters*

Searches can be limited to one platform and one Scala version:

  platform   `jvm`, `js` (Scala.js), `native` (Scala Native), `sbt` (sbt
             plugins) or `mill` (Mill plugins)
  scala      `3`, `2.13`, `2.12`, `2.11` or `2.10`

Set them for every search with `platform` and `scala_version` in
|scaladex-configuration|, or for one search as |:Scaladex| arguments, which
complete with <Tab>: >vim
    :Scaladex platform=js scala=3 json parser
<
An empty value, as in `platform=`, searches every platform even when a
default is configured.

To change the filters after searching, pick "Change filters…", the first
entry of the project list (<C-f> in |scaladex-telescope|). You choose a
platform, then a Scala version, each listed with how many results it gives
and the current choice marked with `*`, and the search runs again.

==============================================================================
7. TELESCOPE                                              *scaladex-telescope*

With telescope.nvim, load the extension for pickers with previews: >lua
    require("telescope").load_extension("scaladex")
<
Then use `:Telescope scaladex` or
`require("telescope").extensions.scaladex.search(opts)`. Besides the usual
Telescope options, `opts` takes `query`, `platform`, `scala_version` and
`action`: >
    :Telescope scaladex query=http4s platform=jvm scala_version=3
<
Mappings, in insert and normal mode:

  <CR>   apply the configured action (projects: show the modules)
  <C-s>  open the package page in the browser
  <C-y>  copy the dependency line (modules only)
  <C-f>  change the platform and Scala version filters (projects only)

8. LUA API                                                      *scaladex-api*

All functions are on `require("scaladex")`. Those that make a request run
in the background when given a callback, which is called on the main loop as
`callback(err, value)`. Without a callback they block and return
`value, err`.

search({query}, {opts}, {callback})                         *scaladex.search()*
    Searches pkg.scalanews.net. {opts} may set `platform`, `scala_version`
    and `page` (see |scaladex-filters|); filters left out fall back to the
    configured ones, and `""` means any. Returns a list of projects, each
    with `title`, `key` and `packages`: the modules worth showing for the
    query (`groupId`, `name`, `latestVersion`, `targets`, `project`, …).
    The whole response is passed last, after the error: `total`, `results`
    and `facets`, the result counts per platform and Scala version.

get_package({group_id}, {name}, {callback})            *scaladex.get_package()*
    Gets one package, e.g. `("org.typelevel", "cats-core")`: its `summary`
    and `install` snippets for sbt, Mill and scala-cli. Nil when there is no
    such package.

package_url({group_id}, {name})                        *scaladex.package_url()*
    The pkg.scalanews.net page of a package.

dependency({package}, {buf})                            *scaladex.dependency()*
    The line that adds a package (one of a search result's `packages`) to
    the build of buffer {buf} (default: current). See |scaladex-build-tools|.

pick({opts})                                                  *scaladex.pick()*
    What |:Scaladex| runs. {opts} may set `query`, `platform`,
    `scala_version` and `action`.

==============================================================================
9. HEALTH                                                    *scaladex-health*

`:checkhealth scaladex` checks the Neovim version, that `curl` is installed,
that pkg.scalanews.net answers, and whether Telescope is available.
